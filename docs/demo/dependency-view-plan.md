## 外部依赖：ETA 与期望时间分离 + 依赖视图（Demo 方案）

> 状态：**已实现**（2026-10-21）。`docs/demo/roadmap-demo.html` 保留为设计参考；生产行为与接口说明见下文。

### 1. 两个时间概念

| 概念 | 字段 | 谁说了算 | 来源 | 如何修改 |
|---|---|---|---|---|
| **ETA**（对方承诺） | `eta` + `etaSource: 'jira' \| 'manual'` + `etaAt` | 对方 | 绑定 ticket → 该 ticket 的 **Target End**；没有 ticket，或 ticket 没填 Target End → 手动填写对方给的日期 | **单击**节点 → 刷新（ticket）或填写（手动） |
| **期望**（我们需要） | `need`，`null` 表示与 ETA 相同 | 我们 | 默认为空；没有 ETA 时取默认值 | **拖动**节点 |
| Ticket 排期（只读镜像） | `jiraTargetStart` / `jiraTargetEnd` / `jiraStatus` | 对方 | 打开页面时静默刷新 | 不可改，只用来展示，以及判断「Jira 有变更」 |

操作习惯固定为：**拖动改我们的时间，单击改对方的时间。** 我们的时间由自己决定，所以直接拖；对方的时间只能读取或抄录，所以要单击才会改。

### 2. 派生值

```
gap  = need && eta ? diffD(need, eta) : 0     // >0：对方比我们期望的晚 gap 天
done = jiraStatus ∈ {Done, Closed, Resolved}
state =
  done                                  → 'done'     已交付
  !eta && jiraKey && jiraTargetEnd      → 'stale'    Jira 已有 Target End，待刷新
  !eta                                  → 'missing'  缺 ETA
  gap > 0                               → 'late'     晚于期望（红）
  eta ≠ jiraTargetEnd（有 ticket 时）    → 'drift'    Jira 有变更（琥珀）
  其余                                   → 'ok'       按期 / 有余量
风险排序：late < missing < stale < drift < ok < done
```

页面打开时的静默刷新**只更新镜像字段**（`jiraTargetEnd` 等），不改 `eta`。这样对方改了日期时，我们会看到 drift 提示，而不是节点自己移位。

### 3. 添加依赖

| 输入 | 行为 |
|---|---|
| 有 Jira Key，ticket 有 Target End | 自动读取：`eta = Target End`，`etaSource = 'jira'`，`need = null`。节点放在 ETA 上 |
| 有 Jira Key，ticket 没有 Target End | 等同于没有 ticket：`eta = null`。节点放在默认期望日（任务开始日，已开始的任务取今天 + 7 天） |
| 有 Jira Key，未装扩展 | 照常保存。不读取，提示稍后单击节点刷新 |
| 没有 Jira Key | 可以手动填写对方的 ETA，也可以留空。留空时节点放在默认期望日 |
| 表单里填了期望时间 | 写入 `need`（与 ETA 同一天时写入 `null`） |

### 4. 甘特上的节点（简洁版）

| eta | need | 展示 | 拖动 | 单击 |
|---|---|---|---|---|
| ✓ | 空或等于 ETA | 实心圆点在 ETA | 从圆点上拖出一个期望环，**ETA 点不动** | 打开依赖浮层，聚焦这一条 |
| ✓ | 早于 ETA | 实心红点（ETA）+ 虚线环（期望）+ **红色连线** + `+Nd` | 拖圆点或虚线环都改期望 | 同上 |
| ✓ | 晚于 ETA | 实心点 + 淡色虚线环 + 灰色点线（有余量） | 同上 | 同上 |
| ✗ | ✓ | 红色虚线环 + `?` 在期望日，角标红色脉动 | 改期望 | 填写或刷新 ETA |
| ✗ | ✗ | 不上标记轨，只显示角标 | — | — |

- **吸附合并**：期望拖到距 ETA ±1 天以内时吸附到 ETA，松手后 `need = null`，两个点合成一个。
- **多个依赖**：同一任务上多对节点共用一条标记轨。hover 某个节点时，同一依赖的另一个节点和连线高亮，其余依赖淡化。完整关系在依赖视图里看。
- 角标优先级：缺 ETA（红色脉动）> 晚于期望（红色）> Jira 有变更（琥珀）。

### 5. 依赖视图（完整版）

- 入口：工具栏「任务 / 人员 / **依赖**」。只列出**有依赖的任务**，按任务分组。组头用一条淡色任务条标出任务排期，作为上下文。
- 每个依赖一行。左侧是状态 pill、依赖内容、ticket、status 和对方团队；右侧是时间轴：
  - 上面一行是 ETA 实心点和期望虚线环。两者之间：晚于期望时用**红色半透明带 + 红线 + 「晚 Nd」**，有余量时用灰色点线 + 「余量 Nd」。
  - 下面一行是 ticket 的 Target Start → End（斜纹细条，只读）。
  - Jira 有变更时，在新的 Target End 处画一个琥珀色空心点，用虚线箭头接到当前 ETA 上。
  - 缺 ETA 时画期望环，向右接一段渐隐虚线和 `?`。
- 操作：拖动圆点或环改期望（和甘特一致，支持键盘 ← → / Shift 一次 7 天）；行内「刷新 ETA」「催一下（附上期望日期）」「接受 ETA」（期望改为跟随 ETA）。
- 过滤：全部 / 晚于期望 / 缺 ETA / Jira 有变更，计数实时更新。组内和组间都按风险排序。
- 在甘特的依赖浮层里点「在依赖视图中查看」，会跳到依赖视图并闪烁定位到这一行。

### 6. 生产实现

- 兼容现有结构：`item.markers[]` 中 `kind: 'dep'` 的 `date` 仍是已确认 ETA，增加 `need`（nullable）、`etaAt`（确认时间戳）、`jiraTargetStart`。`need = null` 跟随 ETA；历史数据迁移不改原 ETA。
- 数据库迁移：`022_dependency_expectation`，在 `item_markers` 上增加 `need` / `eta_at` / `jira_target_start` 三个可空字段。
- 现有 `POST /api/v1/teams/:teamId/intents`：`add_marker` 支持新字段和首次读取的 Jira 镜像；`update_marker` 支持 `need` 与 `jiraTargetStart`，沿用 `baseVersion` 乐观并发校验。仅改期望或镜像不改 `etaAt`；显式设置/清空 `date` 更新/清空确认时间。
- `refresh_from_jira` 同步 Target Start/End 和 status，只写镜像，不改变 ETA/期望、不增加 marker version。显式刷新才将非空 Target End 写入 ETA；无 Target End 时保留已有已确认 ETA，允许手动填写。
- 前端：`dependency.ts` 统一派生风险、过滤、排序及吸附规则，`DependencyTrack.vue` 被甘特与 `DependencyView.vue` 共用；方向键与拖动改期望，可撤销，冲突按既有机制刷新。
- 扩展：复用现有 `pai-roadmap-refresh-jira` 批量接口读取两种 Target 日期，无须修改或重新加载扩展。Jira 实际数据需已安装的 Personal AI 扩展提供。
- 「催一下」复制包含期望时间的跟进文案并打开 Jira，由用户粘贴发送。

### 7. 复制联动（用户追加需求）

- 工具栏「依赖」激活时，右上角复制只导出当前任务搜索 / Milestone 与依赖风险筛选后的依赖，顺序与依赖页一致。
- 始终包含：Ticket（无 ticket 标记手动依赖）、依赖内容、所属任务、期望日期、ETA、风险/余量、Jira 状态、Target Start、Target End。
- 支持列表（文档/聊天）和表格（Sheet/TSV）两种格式，带 Jira 超链接；缺 ETA/期望会明确标记。复制格式按三个视图分别记忆。
- 任务/人员视图继续使用各自的复制范围。没有依赖时显示空态。

### 8. 在甘特中定位（依赖视图 / 人员视图 → 任务视图）

**结论：做成独立的「定位」导航，不复用顶部的全局搜索。**

| | 复用顶部搜索 | 独立定位（采用） |
|---|---|---|
| 语义 | 搜索是**过滤**：改变结果集 | 定位是**一次性视口导航**：只移动视口 |
| 对依赖视图 | 搜索同时作用于 Backlog / 甘特 / 依赖视图 / 复制计数。写入关键词会覆盖用户原来的搜索，回到依赖视图时列表已经变了，**会污染筛选** | 不写 `search`、Milestone 和依赖风险筛选；返回后筛选和滚动位置都保持原样 |
| 甘特上下文 | 其它行全部被过滤掉，看不到前后排期 | 保留整张甘特，只把目标滚到视口中央并高亮 |
| 子任务 / 依赖节点 | 搜索只能命中 Epic，或按标题模糊匹配，无法精确到某个依赖节点 | 可以精确到 Epic、子任务（自动展开父 Epic）或某个依赖的 ETA / 期望节点 |
| 结束 | 用户得自己清空搜索 | 不需要清理：Esc、×、手动切换视图都会结束定位 |

**入口**
- 依赖视图组头：点**主任务名**，或者 hover 时出现的 ⌖，定位到这条 Epic。
- 依赖行 hover 操作里的「⌖ 甘特」：定位到这条依赖在标记轨上的节点（ETA 实心点，没有 ETA 时是期望环），同时点亮配对的节点和连线。
- 人员视图任务条：hover 时右端出现 ⌖。这是独立按钮，并阻止冒泡，不会触发「正在做」的选中。点击后展开父 Epic，定位到这条子任务。

**落点**
- 切到任务视图后，目标水平放在约 30% 处，垂直放在约 35% 处（平滑滚动，系统开启「减少动态效果」时直接跳）。
- 目标会脉冲高亮 2.4 秒，所在行同时铺一层浅蓝底色。
- **目标被当前过滤隐藏时**，例如 Milestone 设为「隐藏」：不改过滤条件，只把这一行**临时显示**（斜纹底色），并标注「临时显示 · 不在当前 Milestone 过滤内 ×」。点 ×、返回原视图或切换视图后恢复隐藏。
- 工具栏出现「← 返回依赖视图 / 人员视图 · 已定位 XXX ×」。点返回会回到来源视图，恢复原来的滚动位置并闪烁来源行。

**生产实现**
- URL 用独立参数 `focus=<itemKey>[:sub:<id> | :dep:<id>]`，与现有 URL 参数（`q=` 为 Quarter）及搜索筛选互不影响，刷新或分享后能复现定位。
- 定位状态放在 `useRoadmapState` 的 `locate` 中，保存来源视图、横纵滚动位置及精确目标；不进入快照，也不和其他人同步。
- 生产实现只在 `GanttRow` 对当前定位行豁免隐藏/淡化，保持公共 `viewMatch(item)` 不变，避免污染 Backlog、复制和筛选计数。
- 无效、被删除、已清理或退回 Backlog 的目标会给出提示并结束定位；父任务自动展开只改变本人的 UI 状态。
- 依赖聊天复制使用 `- Depends on …` 纯文本列表；富文本输出真正的 `<ul><li>`，两个 ticket 的链接保留。
